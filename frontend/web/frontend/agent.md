# agent.md

## Цель
Поддерживать фронтенд проекта в предсказуемом, расширяемом состоянии без роста дублирования и без поломки русской кодировки.

## Ключевые правила
- Все новые файлы и правки сохранять в UTF-8.
- Не смешивать относительные «глубокие» импорты и alias-импорты: в приложении использовать `@/...`.
- Для одинаковой бизнес-логики всегда делать один источник правды (утилита/хук/модель) и переиспользовать его.
- UI-компоненты должны быть тонкими: бизнес-правила выносить в `model` или `shared/lib`.
- Любые технические дубли (например, snake/kebab версии одного файла) сразу объединять через реэкспорт или удаление.

## Архитектурные ориентиры
- `entities/*` — доменные типы и справочники.
- `features/*` — пользовательские сценарии (импорт, выбор параметров и т.д.).
- `widgets/*` — композиция сценариев и отображение данных.
- `shared/lib/*` — переиспользуемая логика без UI.
- `shared/ui/*` — универсальные UI-элементы.

## Как добавлять новую функцию
1. Определить доменную модель (types/dto/валидация).
2. Вынести вычисления и правила в `shared/lib` или `features/<name>/model`.
3. Сделать минимальный UI-слой, использующий готовую логику.
4. Проверить, не дублирует ли функция существующие модули.
5. Прогнать `npm run lint` и `npm run build`.

## Чеклист перед merge
- Нет битых импортов.
- Нет дублирующих утилит с разными именами.
- Нет отладочных `console.log`/`console.error` в production-коде.
- Русский текст отображается корректно, файл сохранен в UTF-8.
- Линтер и сборка проходят.
